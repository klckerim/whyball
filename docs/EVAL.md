- **v3 (slot)**: the model writes no concrete values; it writes a placeholder template + claims, and code renders the values from the verified claims. - **v5 (claim menu)**: code builds and verifies the claims (`app/explain/menu.py`); the model links no claims or events and only uses menu ids (`{value:}`, `{minute:}`, `{start:}`, `{label:}`, `{clause:}`, `{event:}` for menu evidence, `{score}`). Extra rules: an id not on the menu, a sentence not grounded in a menu claim, a dominance/pressure moment without its primary claim, and the same minute twice in one sentence are rejected; the only allowed EN sentence start is "The". The model writes no claims, so injections that change a claim (`number_text_and_claim`) are "—" in v5.
- Bases: v3 `slotify` 248/248, v4 `slotify_v4` 248/248, v5 `slotify_v5` 248/248 drafts converted cleanly (the v4 base passes both the v4 and v4.1 rules); the columns are measured on these.
- Each error type is injected in each approach's own form, with the same meaning (seeded by moment + type + language + version). A draft the injection cannot apply to is not in N; "—" is a type with no counterpart in that approach. Types marked "(new, v4)" / "(new, v4.1)" were added in that version.
- **Caught** = the check returned at least one error; the pipeline does not publish the draft in that case.

The text states the clipped window's start, so it is not misleading, but it does not match the detector's value (moment.detail) exactly.
- `goal`, `red_card`, `penalty`: claims are at the event or kickoff → now; no separate window.
